# 方針1実装結果と方針2への移行

**作成日**: 2026年1月13日

---

## 方針1の実装結果

### 実装内容

1. **階層的ドロップダウンのPOSTバックを順次実行**
   - 大分類 → 中分類 → 小分類の順にPOSTバックを実行
   - `txtLgKikanInf2SelIndex_h`を正しく設定

2. **`txtLargeKikanInf_h`から小分類の選択肢を取得**
   - `_parse_txtLargeKikanInf_h`メソッドを使用
   - 中分類のvalueに一致する小分類の選択肢を抽出

### 問題点

1. **`txtLargeKikanInf_h`に小分類のデータが含まれていない**
   - 中分類のPOSTバック後も、`txtLargeKikanInf_h`には初期ページから取得できるデータのみが含まれている
   - 「東北地方整備局」のデータが含まれていない

2. **小分類の選択肢が読み込まれない**
   - 中分類のPOSTバック後のHTMLに小分類の選択肢が含まれていない
   - JavaScriptで動的に読み込まれるが、`requests`ライブラリでは実行できない

### テスト結果

```
検索条件:
  大分類: 国の機関
  中分類: 国土交通省
  小分類: 東北地方整備局

結果:
  - txtLargeKikanInf_hから小分類の選択肢を1個取得
  - しかし、「東北地方整備局」の値が取得できず
  - 検索結果に「関東地方整備局」の案件が含まれる
```

## 方針2への移行

### 理由

1. **方針1の限界**
   - JavaScriptで動的に読み込まれる小分類の選択肢を取得できない
   - `txtLargeKikanInf_h`に必要なデータが含まれていない

2. **方針2の利点**
   - 確実に動作する
   - 検索結果ページから各案件の情報を抽出してフィルタリングできる
   - JavaScriptの実行を模倣する必要がない

### 実装方針

1. **検索結果ページから各案件の情報を抽出**
   - 発注機関名
   - 工事名
   - 工事場所
   - その他の検索条件

2. **検索条件と照合**
   - 各案件が検索条件に一致するか確認
   - 一致しない案件のファイルを除外

3. **フィルタリングの実装**
   - `Filter`クラスに新しいメソッドを追加
   - 検索結果ページのHTMLを解析して各案件の情報を抽出
   - 検索条件と照合してフィルタリング
