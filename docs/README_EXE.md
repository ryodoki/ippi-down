# ippi-down（Windows exe版）

このパッケージは、i-ppi.jpの公開検索画面から条件に一致する文書を取得し、Windows PCのローカルフォルダへ保存するGUIツールです。

正式な対象環境はWindows 10/11 x64、ローカル保存です。HTML形式の入札調書は同梱の日本語フォントを使う内蔵生成器でPDF化し、内蔵生成に失敗した場合だけMicrosoft Edgeを監視付きで使用します。

## 起動

`ippi-down.exe`をダブルクリックして起動します。

初回は画面の設定からデータルートと検索条件を確認してください。設定ファイルを手動で用意する場合は、`config/config.example.yaml`を`config/config.yaml`へコピーして編集します。

実設定、ログ、取得文書はこの配布zipに含まれていません。実行後はexeと同じ場所を基準に、`config/`、`logs/`、`downloads/`を使用します。

## 保存フォルダー

保存先、分類、命名、履歴、旧構成との互換性に関する正本は、同梱の[ダウンロードフォルダー仕様](download_folder_spec.md)です。

`save_paths.local`は工事・業務、通常実行、定期実行をまとめるデータルートです。新規設定の`layout_version: 4`では次のように分けます。

```text
<データルート>\
├─ 工事の検索（入札の経過）\
│  ├─ 01_通常ダウンロード\
│  └─ 02_定期実行\S001_<設定の初回名称>\
└─ 業務の検索（入札の経過）\
   ├─ 01_通常ダウンロード\
   └─ 02_定期実行\S002_<設定の初回名称>\
```

検索対象は「工事（入札の経過）」と「業務（入札の経過）」から選択します。発注機関の大～小分類は対象別の公式「発注機関複数選択」ツリーから取得し、細分類と送信値の検証、案件検索、文書取得には工事で`tab=4`、業務で`tab=7`を使用します。分類を確定できない案件は`99_分類未解決`へ保存します。v3からv4への切替は設定保存時に確認し、旧構成のファイルと履歴は自動で移動、改名、削除しません。正確なフォルダー生成、ファイル命名、履歴再利用、版管理は正本仕様を確認してください。

設定画面の「データルート」にある「保存済みファイルを再分類...」では、通常実行と各定期実行の履歴から、`99_分類未解決`にある検証済みファイルの候補を確認できます。実行区分、定期設定名、案件・文書、現在位置、移動先、理由、可否をプレビューし、選択して確認した候補だけを同じ検索対象・実行ルート内で再分類します。移動先に同内容の検証済みファイルがある場合は移動先を正本として履歴化し、旧ファイルは削除せず保持します。ダウンロードまたは定期実行が実行中・順番待ちの場合は開始できません。検索、設定保存、プレビューだけで既存ファイルを移動することはありません。

## メモリと一時資源

長期利用時の履歴読込み、GUI保持上限、候補ワーカー、定期実行dispatcher、一時物回収の正本は、同梱の[メモリ・一時資源の運用仕様](memory_resource_management.md)です。GUIログは5,000行または2 MiB、定期実行の詳細ログは直近200件または2 MiBまで表示し、完全な記録はファイルへ残します。

## 定期実行

設定画面の「定期実行」タブでは、名前付きの実行設定を複数保存して一覧管理できます。各設定に検索条件、文書条件、命名規則、保存先、毎日／毎週／毎月の予定、再試行設定、通知方針を保持し、追加、複製、編集、削除、有効化／無効化、修復、今すぐ実行、履歴確認を行えます。有効な設定ごとに不変の条件スナップショットとWindowsタスクを登録します。GUIを閉じた後も実行され、開始済みの処理はGUI終了の影響を受けません。追加・複製・編集・削除・有効切替は操作ごとに登録情報へ反映されます。設定画面下部の「保存」は一般設定用であり、操作後の「キャンセル」では定期実行の変更を取り消せません。

管理対象の設定は、実行中・順番待ち・再試行待機中でも複製、編集、削除、有効化／無効化できます。編集を選ぶと確認画面が開き、開始済み・待機済みの実行は登録時の条件で続け、変更後の条件は次回以降に反映します。削除や無効化の確認画面でも、進行中の実行が続くことを案内します。「今すぐ実行」は実行中・順番待ちには使用できません。管理外の旧Windowsタスクは通常の編集対象ではありません。狭い画面では操作ボタンが折り返されます。設定画面下部の保存・キャンセルは表示したまま、定期実行の内容と履歴をスクロールして確認できます。

Windowsタスクは配置ごとの`task namespace ID`を`config/schedule-instance-id`へ保持し、`\ippi-down\Download-<task-namespace-id>-<schedule-id>`として登録します。フォルダー一式を移動した場合は同じ配置として追従し、exeだけを別フォルダーへコピーした場合は新しい配置になります。`%LOCALAPPDATA%\ippi-down\install-id`は全配置の実行をFIFOで直列化する`coordination ID`であり、別配置のタスクを現在の配置が所有する根拠には使用しません。別配置のタスクは設定画面の「管理外の旧Windowsタスク（通常の保存条件とは別管理）」に表示し、メイン画面では通常一覧に混在させず「管理外の旧タスク」の件数だけを表示します。

配置フォルダー一式を移動または改名すると、`config/install-location.json`に記録した確認済み位置との差を起動時に検出します。旧配置が残っていても、確認後に旧配置内を指す保存先・ログと定期実行の起動情報だけを現在位置へ付け替えます。別ドライブ等の外部保存先は変更せず、旧snapshot、既存文書、履歴、ログ、旧フォルダーも移動・削除しません。変更開始前に配置移行journalを保存するため、途中終了後は非GUI実行を停止し、次回のGUI確認から残処理を再開します。旧配置には廃止済みの管理情報を残し、本版以降のプログラムによる誤起動を停止します。移行機能を持たない旧版exeは廃止情報を解釈できないため、移行確認後は旧ショートカットを外し、旧配置を起動対象にしないでください。付け替えが完了するまではダウンロードと設定保存を停止します。

定期設定には登録時に`S001`のような固定保存キーを割り当てます。表示名を後から変更しても`S001_<設定の初回名称>`フォルダーは改名しません。設定を複製した場合は新しいキーと保存フォルダーを発行し、元設定とは保存履歴を分けます。

定期実行はWindowsの`InteractiveToken`方式で、登録した同じWindowsユーザーがログオン中の場合だけ開始します。画面ロック中は実行できますが、サインアウト中は実行できません。Windowsのパスワードは保存しません。`実行漏れ時にPC起動後1回だけ実行`（`StartWhenAvailable`）は次回利用可能時に1回だけ補完します。`スリープを解除して実行`（`WakeToRun`）がOFFなら復帰後に補完し、ONならWindowsとPCの電源ポリシーが許す範囲で予定時刻にスリープを解除します。ネットワーク利用可能時だけ開始し、スリープ解除の既定はOFFです。複数設定やGUI手動実行と重なった場合は並列取得せずFIFOで待機し、待機上限2時間、実処理上限2時間、タスク全体の上限4時間です。

通知方針は設定ごとに「通知しない」「重要な結果のみ（新規保存・失敗など）」「すべての実行結果」「失敗時のみ」から選択できます。既存設定はOFF、新規設定は「重要な結果のみ」が既定です。重要な結果とは、新規保存が1件以上あるか、一部失敗、全件失敗、キャンセル、設定不正、キュー待機・実行上限、予期しないエラーです。全件保存済みと正常な該当なしは「重要な結果のみ」では通知しません。「テスト通知」でWindows通知経路を確認できます。

通知は再試行途中やFIFO受付時には出さず、最終結果の履歴保存後に`run_id`ごと1回だけ出します。Windows標準の`Shell_NotifyIconW`を使うため、定期実行通知に`win10toast`は不要です。通知内容は設定名、最終結果、新規・保存済み・失敗件数、先頭理由コードだけで、検索条件、URL、Cookie、保存先は含みません。クリック操作はありません。集中モード、Windows通知設定、企業ポリシーで表示されない場合があり、通知失敗もダウンロード結果と終了コードを変えません。正本は「実行履歴」、`logs/schedule-runs.jsonl`、`logs/app.log`です。

メイン画面では保存設定数、有効数、実行中、順番待ち、要修復、前回失敗の集計と、各設定の予定、次回／前回日時、結果、新規保存・保存済み確認・失敗件数を一覧で確認できます。定期実行欄には「GUI終了後も実行可」「Windowsログオンが必要」とスリープ解除の設定状態も表示します。一時障害の次回試行待ちは「再試行待機中」と表示します。「今すぐ実行」は選択中の有効な設定の登録済みスナップショットをWindowsタスク経由で開始します。

「実行履歴」には選択設定または全設定の直近20回の予定・開始・終了、起動種別、キュー待機、結果、件数、再試行、理由コードを表示します。Windowsタスクから元のトリガー日時を取得できない実行では、予定日時にタスクの実行要求時刻を記録します。同じ内容は`logs/schedule-runs.jsonl`へ記録され、設定削除後も検索条件を含まない診断履歴だけは残ります。自配置の実行ファイル、引数、スナップショット、タスク定義の欠落・不一致は「要修復」と表示し、別配置のタスクは「別配置」として分離します。「要修復」でタスク自体が起動できない場合は通知も出せないため、GUIの表示と修復操作で診断してください。

定期実行のdispatcherと通知用ウィンドウは処理中だけ存在する短命のものです。常駐トレイ、常駐通知監視、Windowsサービスは起動しません。GUIを閉じ、ジョブと通知が完了した後はippi-down由来のプロセスは残らず、その時間のCPU、メモリ、ネットワーク負荷はありません。

旧版のプロセス内スケジュールと別配置の設定は自動移行しません。「旧設定を取り込む...」で移行元の`config`フォルダーを選び、設定名、有効状態、実行予定、実効保存先、可否、Windowsタスク名、診断のプレビューから1件を選びます。検証できない候補は取り込めません。同名候補は「要改名」となり、「取り込み後の設定名」へ1～80文字の一意な名前を入力します。移行先は一時的に無効で作成し、旧タスクを無効化してから元の有効／無効状態を引き継ぎます。元が有効なら現在のexeを使う移行先を有効化し、元が無効なら移行先も無効のままです。その後、移行元を移行済み（内部状態`MIGRATED_OUT`）として記録し、旧Windowsタスクを削除します。削除に失敗した場合は旧タスクを無効のまま残し、「旧設定の取り込み完了（後処理警告） `[EXTERNAL_TASK_CLEANUP_PENDING]`」と表示します。旧配置の同じ設定に属する実行履歴は現在の履歴へ統合し、失敗時は警告しますが設定の移行は維持します。台帳や検証可能なスナップショットがない孤立タスクは取り込めず、「選択した外部タスクを解除」から確認して解除だけを行えます。実行中の外部タスクは解除できません。旧`config`、既存の取得文書、元の実行履歴は削除、移動、改名しません。

## 発注機関候補の読み込み

起動時と、工事／業務を初めて切り替えた時に、現在対象の公式「発注機関複数選択」画面を取得し、大分類、中分類、小分類を対象別メモリへ展開します。準備後の大～小分類のプルダウン切替では追加通信を行いません。候補、Session、WebForms hiddenは対象間で共有せず、ディスクにも保存しません。

細分類は必要な枝だけをバックグラウンドまたは選択時に取得し、同じ枝を再度選んだ場合はメモリ上の結果を使用します。未取得の間は対象の下位プルダウンに「読み込み中…」と表示されます。「候補を再読み込み」は発注機関4階層、地域、工事／業務区分を取り直し、全体解析に成功した時だけ新世代へ全置換します。設定、履歴、保存済み文書は変更せず、定期ポーリングも行いません。

実際の検索では常に対象別リスト検索画面で表示名を最新コードへ再解決します。存在しない保存済み条件は画面末尾に保持したまま`AGENCY_SELECTION_REMOVED`で保存・検索を止めます。更新失敗時は旧候補を参照表示用に残しますが最新扱いせず、発注機関指定があれば`AGENCY_CATALOG_REFRESH_FAILED`で停止します。発注機関未指定の検索は不必要に停止しません。ログには対象、階層、候補件数、追加・削除件数、結果コードだけを記録し、HTML本文、Cookie、hidden値は記録しません。

## 検索結果の確認

すべての検索結果と各案件の詳細ページを解析してから集計を表示し、ダウンロードへ進みます。取得完了後は新規・更新件数と保存済み確認件数が確定値へ更新されます。

```text
検索解析完了：案件13件 / 公開中データ14件 / 公開終了のみ7件
今回の対象：14件（新規・更新0件 / 保存済み確認14件〈旧命名14件〉）
```

「案件・文書内訳」では、対象となった案件の発注機関階層、分類状態、分類理由、保存予定フォルダーと、その案件にある公開中・公開終了文書、最終更新日時、掲載終了日時、今回の判定を確認できます。判定は新規・更新、保存済み、旧命名を再利用、公開終了、ファイル種別・キーワード・日付による対象外、公開中リンクなしなどを区別します。`すべて`、`DL対象あり`、`公開終了のみ`、`文書なし`、`確認不能`、`分類未解決`の絞り込みと、案件・文書・分類情報による検索を利用できます。

検索条件で「公開中のみ」を有効にした場合、HP側で公開終了案件が検索結果から除外されます。そのため、公開終了のみの案件数は0件とせず、`集計対象外`と表示します。

## ファイル名と保存済みファイル

既定の命名規則は`{document_name}_{document_updated_at}`です。HPの文書名称と最終更新日時から、例えば`設計書_20260529_1358.pdf`として保存します。

更新日時が取得できないときは現在時刻や案件の公告日時を使わず、`設計書_更新日時不明_18.pdf`のように安定した文書IDを付けます。同じ文書名称・更新日時のファイルが衝突した場合も、該当ファイルだけ文書IDを末尾に追加します。

旧版の既定値`{category}_{title}_{date}_{index}`だけは設定読み込み時に新しい既定値へ自動移行します。利用者が設定した別のカスタム命名規則は維持します。

旧名称で保存済みのファイルは改名しません。URL、期待形式、HPの文書最終更新日時と取得日時、サイズ、SHA-256、PDF署名・終端またはOOXML構造を検証できた場合だけ、旧名称のまま保存済みとして再利用します。HP側に新しい更新日時がある場合は、新しい名前で別ファイルを取得して旧ファイルも残します。

配布後の動作条件は、コマンドプロンプトまたはPowerShellから次の自己診断で確認できます。

```powershell
.\ippi-down.exe --self-check
```

この診断は、一意な診断用Windowsタスクの登録・照会・削除、内蔵PDF生成、同梱フォント、Edge用Job Object監視機構、保存済みの入札調書サンプルを使ったオフライン一時PDF生成、PDF署名・終端・サイズ・SHA-256・A4縦MediaBox、一時ファイルの後処理まで確認します。Edge本体はフォールバックであり、未導入だけでは内蔵生成の自己診断を失敗にしません。通常の定期実行タスクや検索条件は変更しません。正常時の終了コードは0です。診断結果はexeと同じ場所の`self-check-result.txt`にも記録され、失敗時は日本語理由と理由コードを確認できます。

## 通信と安全性

通信先、ローカルプロセス、保存先、監査方法の完全な仕様は、同梱の
[外向き通信・ローカル実行セキュリティ仕様](network_security.md)を確認してください。

- 接続先はi-ppiの固定された公式HTTPS endpointだけです。各送信と
  リダイレクトをMethod、host、path、query形式、用途で検証し、任意URL、
  proxy、TLS検証無効化、telemetryは許可しません。
- 設定、ログ、保存先はローカルの固定またはリムーバブルドライブだけです。
  UNCとネットワークドライブは使用できません。
- 許可／拒否の安全な記録は`logs/network-audit.jsonl`、詳細な理由は
  `logs/app.log`で確認できます。query値、Cookie、HTTP本文は監査ログへ残しません。
- HTTP試行は初回を含め最大3回です。
- 既定の通信間隔は1リクエスト/秒で、再試行対象応答では`Retry-After`を優先します。
- 取得中のデータは`.part`へ保存し、検証完了後に正式名へ置換します。
- `.pdf`を取得対象にすると、HTML形式で配信される正常な「入札調書」も内蔵生成器で自動的にPDF化します。
- 変換PDFはA4縦、余白10mm、ブラウザーの日時・URLヘッダー／フッターなしです。生成後に案件名と帳票全文字列を再読込して検証します。
- 内蔵生成に失敗した場合だけ、検証・安全化した一時HTMLをMicrosoft Edgeへ渡します。EdgeはWindows Job Objectで全子プロセスを監視し、一時障害だけ独立profileで最大2回試します。対象サイトへ再接続させず、別ブラウザーへも切り替えません。
- 変換イベントは`logs/pdf-conversions-YYYY-MM-DD.jsonl`へ90日保持し、GUIの「PDF変換履歴」で直近200件を確認できます。全方式失敗時の無害化済みHTML等は`logs/pdf-failures/<変換ID>/`へ30日保持します。業務情報を含むため外部へそのまま提供しないでください。
- `SHA256SUMS.txt`には`ippi-down.exe`のSHA-256が記載されています。

組織の企業ポリシーでEdgeのヘッドレス実行が禁止されていても、通常は内蔵生成器で処理できます。内蔵生成とEdgeフォールバックがともに失敗した場合は、`--self-check`と「PDF変換履歴」で理由コード、プロセス終了コード、変換IDを確認してください。詳細仕様は同梱の[入札調書PDF生成・監視仕様](pdf_conversion_reliability.md)を参照してください。

## 現在提供しない機能

- Boxへの保存・認証
- 並列ダウンロード

問題が発生した場合は、GUIの「PDF変換履歴」に表示される日本語理由と理由コードを確認し、`logs/app.log`と日別PDF変換ログを参照して管理者へ連絡してください。主な変換関連コードは`PDF_INTERNAL_RENDER_FAILED`（内蔵生成失敗）、`EDGE_SUPERVISION_UNAVAILABLE`（全プロセス監視不可）、`EDGE_GPU_PROCESS_CRASH`（GPUプロセス障害）、`EDGE_PROCESS_CRASH`（Edge異常終了）、`EDGE_OUTPUT_NOT_PRODUCED`（出力なし）、`CONVERSION_TIMEOUT`（時間超過）、`HTML_STRUCTURE_INVALID`（必須項目不足）、`PROJECT_NAME_MISMATCH`（案件名不一致）です。ログ、設定、障害資料には業務情報が含まれる可能性があるため、公開場所へ添付しないでください。
