# ppi-file-downloader 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
ppi-file-downloader

### 1.2 目的
建設情報サービス「ppi.jp」のWebサイトから、ユーザーが指定した条件に基づいてファイルを自動的にダウンロードし、指定したフォルダに整理して保存する自動化ツールを開発する。

### 1.3 対象サイト
- URL: https://www.i-ppi.jp/IPPI/SearchServices/Web/Index.htm
- サイト名: 建設情報サービス

## 2. 機能要件

### 2.1 コア機能

#### 2.1.1 HTM構造解析機能
- **FR-001**: https://www.i-ppi.jp/IPPI/SearchServices/Web/Index.htmのWebページのHTM構造を解析できること
- **FR-002**: ページ内のファイルリンク（PDF、Excelなど）を検出できること
- **FR-003**: HTMの階層構造（ページタイトル、発注機関、工事名（文字列検索）、カテゴリ、日付など）を抽出できること

#### 2.1.2 条件指定機能
- **FR-004**: ユーザーが事前にダウンロード条件を設定できること
  - 対象ページURLの指定
  - ファイルタイプのフィルタリング（拡張子指定）
  - 発注機関や工事名
  - キーワード検索条件
  - 日付範囲の指定
  - その他のカスタム条件

#### 2.1.3 自動ダウンロード機能
- **FR-005**: 指定した条件に一致するファイルを自動的にダウンロードできること
- **FR-006**: ダウンロード進捗状況を表示できること
- **FR-007**: ダウンロード失敗時のリトライ機能を有すること
- **FR-008**: 既にダウンロード済みのファイルをスキップできること（重複回避）

#### 2.1.4 ファイル命名機能
- **FR-009**: HTML構造から取得した情報（ページタイトル、カテゴリ、日付など）を使用してファイル名を自動生成できること
- **FR-010**: ユーザーが命名規則をカスタマイズできること
- **FR-011**: ファイル名の重複を回避する仕組みを有すること

#### 2.1.5 保存機能
- **FR-012**: ユーザーが事前に指定したローカルフォルダにファイルを保存できること
- **FR-013**: フォルダ構造をHTM構造に基づいて自動生成できること（例：発注者別、カテゴリ別、日付別など）
- **FR-014**: Boxクラウドストレージへの保存機能を有すること
- **FR-015**: Box APIを使用して認証・アップロードできること

#### 2.1.6 スケジューリング機能
- **FR-016**: 定期的に自動実行できること（cron形式または設定可能な間隔）
- **FR-017**: 実行ログを記録できること
- **FR-018**: 実行結果を通知できること（メール、ログファイルなど）

### 2.2 補助機能

#### 2.2.1 設定管理機能
- **FR-019**: 設定をファイル（JSON、YAML、INIなど）に保存・読み込みできること
- **FR-020**: 複数の設定プロファイルを管理できること

#### 2.2.2 ログ機能
- **FR-021**: 実行ログを記録できること
- **FR-022**: エラーログを記録できること
- **FR-023**: ログレベルを設定できること（DEBUG、INFO、WARNING、ERROR）

#### 2.2.3 UI機能
- **FR-024**: コマンドラインインターフェース（CLI）を提供すること（開発・デバッグ用）
- **FR-025**: グラフィカルユーザーインターフェース（GUI）を提供すること（必須）
  - プログラミングに詳しくないユーザーでも操作できること
  - 直感的な操作が可能なこと
  - 設定をGUI上で行えること
  - ダウンロード進捗を視覚的に表示できること
  - 実行ログをGUI上で確認できること
- **FR-026**: 実行ファイル形式（.exe等）で配布できること
  - Python環境がなくても実行できること
  - インストール不要で実行できること（ポータブル版）
  - インストーラー版も提供できること（オプション）

## 3. 非機能要件

### 3.1 パフォーマンス
- **NFR-001**: 大量のファイルをダウンロードする場合でも安定して動作すること
- **NFR-002**: ダウンロード処理の並列化を検討すること（オプション）

### 3.2 セキュリティ
- **NFR-003**: Box APIの認証情報を安全に管理すること（環境変数、暗号化設定ファイルなど）
- **NFR-004**: ユーザー認証情報を平文で保存しないこと

### 3.3 エラーハンドリング
- **NFR-005**: ネットワークエラー、ファイルシステムエラーなどに対して適切にエラーハンドリングを行うこと
- **NFR-006**: エラー発生時も処理を継続できること（可能な限り）

### 3.4 保守性
- **NFR-007**: コードに適切なコメントを記述すること
- **NFR-008**: 設定ファイルの形式を明確にドキュメント化すること

## 4. 技術要件

### 4.1 開発言語・フレームワーク
- **TR-001**: プログラミング言語は未定（Python、Node.js、Goなど候補）
- **TR-002**: HTML解析ライブラリ（BeautifulSoup、Cheerio、goqueryなど）
- **TR-003**: HTTPクライアントライブラリ（requests、axios、http.Clientなど）
- **TR-004**: Box SDKまたはBox APIクライアントライブラリ

### 4.2 外部サービス・API
- **TR-005**: Box API（OAuth 2.0認証、ファイルアップロードAPI）

### 4.3 依存関係管理
- **TR-006**: 依存関係を適切に管理すること（requirements.txt、package.json、go.modなど）

## 5. データ要件

### 5.1 設定データ
- 対象URLリスト
- ダウンロード条件（ファイルタイプ、キーワード、日付範囲など）
- 保存先パス（ローカル、Box）
- 命名規則
- スケジュール設定
- Box認証情報（暗号化）

### 5.2 ログデータ
- 実行日時
- ダウンロードしたファイル一覧
- エラー情報
- 実行結果サマリー

## 6. ユーザー要件

### 6.1 想定ユーザー
- 建設情報を定期的に収集する必要があるユーザー
- **プログラミングに詳しくないユーザーも含む**
- **Python環境を持たないユーザーも含む**
- GUI操作が可能なユーザー（Windows環境を想定）

### 6.2 ユーザー操作フロー（GUI版）
1. 初回起動
   - 実行ファイル（.exe）をダブルクリックして起動
   - GUI画面が表示される
2. 設定
   - GUI上でダウンロード条件を指定
     - 対象URLの入力
     - ファイルタイプの選択（チェックボックス等）
     - キーワードの入力
     - 日付範囲の指定
   - 保存先フォルダの選択（フォルダ選択ダイアログ）
   - Box認証情報の設定（オプション、GUI上で入力）
   - 設定を保存
3. 実行
   - 「ダウンロード開始」ボタンをクリック
   - 進捗バーでダウンロード状況を確認
   - ログ画面で実行状況を確認
4. 結果確認
   - GUI上でダウンロード完了を確認
   - ログ画面で詳細を確認
   - 保存先フォルダを開いてファイルを確認

## 7. 制約事項

### 7.1 技術的制約
- ppi.jpのHTML構造が変更された場合、解析ロジックの修正が必要になる可能性がある
- Box APIの利用制限に従う必要がある
- ネットワーク接続が必要

### 7.2 法的・倫理的制約
- ppi.jpの利用規約を遵守すること
- robots.txtを確認し、クローリングが許可されているか確認すること
- 過度なリクエストを送信しないこと（レート制限の考慮）
