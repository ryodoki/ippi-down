# 工事名検索問題の調査結果と修正案

**調査日**: 2026年1月14日

---

## 問題の概要

GUIで「工事名（文字列検索）」に「トンネル」と入力してダウンロードを実行したが、トンネルではない工事もダウンロードされている。

---

## 調査結果

### 1. パラメータの送信状況

調査スクリプト（`test_koji_name_params.py`）の実行結果から、以下のことが確認されました：

- **パラメータは正しく送信されている**: `ctl00$ContentPlaceHolder1$txtKojiName = 'トンネル'`
- **検索結果**: 21件の工事が返ってきているが、すべて「トンネル」を含まない工事
- **「トンネル」を含む工事**: 0件

### 2. 考えられる原因

1. **サーバー側の検索フィルタリングが正しく動作していない**
   - パラメータは送信されているが、サーバー側で検索条件が無視されている可能性
   - または、検索条件の適用方法が異なる可能性

2. **検索フォームの送信方法に問題がある**
   - `btnSearch`パラメータの値が正しくない可能性
   - 他の必須パラメータが不足している可能性

3. **検索結果ページの取得タイミングの問題**
   - 検索結果が正しく取得できていない可能性
   - ページネーションの問題

---

## 修正案

### 方針1: 検索結果ページでフィルタリング（クライアント側）

サーバー側の検索フィルタリングが正しく動作しない場合、検索結果ページで取得したすべての案件から、「トンネル」を含む工事のみをフィルタリングする。

**メリット**:
- サーバー側の問題に依存しない
- 確実にフィルタリングできる

**デメリット**:
- 不要なデータを取得する必要がある
- パフォーマンスが低下する可能性

**実装方法**:
```python
def extract_file_links_from_search_results(
    self, soup: BeautifulSoup, base_url: str, file_types: List[str], search_conditions: SearchConditions = None
) -> List[FileInfo]:
    """検索結果ページからファイルリンクを抽出"""
    file_links = []
    
    # dgrSearchListテーブルを探す
    result_table = soup.find("table", id="dgrSearchList")
    
    if result_table:
        rows = result_table.find_all("tr")
        
        for row in rows:
            # 工事名のリンクを探す
            detail_link = row.find("a", href=lambda x: x and "__doPostBack" in x)
            if detail_link:
                # 工事名を抽出
                koji_name = detail_link.get_text(strip=True)
                
                # 検索条件で工事名が指定されている場合、フィルタリング
                if search_conditions and search_conditions.koji_name:
                    if search_conditions.koji_name not in koji_name:
                        # 検索条件に一致しない場合はスキップ
                        continue
                
                # 詳細ページからファイルを取得
                detail_files = self._extract_files_from_detail_page_via_postback(...)
                file_links.extend(detail_files)
    
    return file_links
```

### 方針2: 検索フォームの送信方法を修正

検索フォームの送信方法を修正して、サーバー側で正しく検索条件が適用されるようにする。

**確認項目**:
1. `btnSearch`パラメータの値が正しいか
2. 他の必須パラメータが不足していないか
3. `__EVENTVALIDATION`が正しく設定されているか

**実装方法**:
- 実際のブラウザで送信されるパラメータと比較
- HARファイルを分析して、正しいパラメータを特定

### 方針3: 検索結果ページの確認

検索結果ページのHTMLを確認して、サーバー側で検索条件が正しく適用されているか確認する。

**確認項目**:
1. 検索結果ページに「トンネル」を含む工事が表示されているか
2. 検索結果ページのHTMLに検索条件が反映されているか

---

## 推奨される修正

**方針1（クライアント側フィルタリング）を採用**し、以下の修正を行う：

1. **`extract_file_links_from_search_results()`の修正**:
   - `search_conditions`パラメータを追加
   - 工事名が指定されている場合、検索結果をフィルタリング

2. **`submit_search_form()`の修正**:
   - `extract_file_links_from_search_results()`を呼び出す際に、`search_conditions`を渡す

3. **ログの追加**:
   - フィルタリングされた件数をログに記録
