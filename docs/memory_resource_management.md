# メモリ・一時資源の運用仕様

この文書は、長時間の検索、保存済み履歴、複数の定期実行を扱う際のメモリと一時資源の上限を定める正本です。保存フォルダーそのものの仕様は[ダウンロードフォルダー仕様](download_folder_spec.md)を参照してください。

## 履歴の読込み

- ダウンロード履歴（`.ippi-download-history.jsonl`）は、起動時に全行をメモリへ展開しません。今回の取得予定にある「URL・相対保存先・期待形式」と「URL・期待形式」だけをストリーム走査で索引化します。
- 履歴JSONLは削除・圧縮しません。大量の履歴があっても、常駐量は履歴全体ではなく今回の対象件数に比例します。
- 定期実行履歴（`logs/schedule-runs.jsonl`）は末尾から読みます。複数設定の最新状態は1回の走査で取得します。
- GUIで表示する定期実行履歴は、選択設定の直近200件かつ2 MiBまでです。完全な履歴はJSONLを「ログを開く」から確認できます。

## GUIの保持上限

- 検索進捗は、更新された工事だけの差分を通知します。ページ終了時と検索完了時だけ全体スナップショットを通知します。
- GUIの正本は工事IDごとに1つだけ保持し、表示できる工事・文書自体は省略しません。
- 通常イベントキューは上限付きです。高頻度の検索進捗は最新値だけを上書きし、完了・失敗・キャンセル通知は優先して必ず配送します。
- GUI内ログは5,000行または2 MiBの小さい方までです。古い表示行はまとめて除去しますが、完全なログはローテーション付きの`logs/app.log`に残ります。
- ウィンドウを閉じると、イベント受信、Tkの予約コールバック、グローバルなマウスホイールbind、候補取得ワーカーを停止・解除します。閉じた詳細／履歴／ログ画面のTreeデータは保持しません。

## HTTP、候補キャッシュ、HTML→PDF

- HTTP応答は所有する呼び出し側が必ず閉じます。通信中の共有Sessionを別スレッドから閉じることはしません。
- 発注機関のWebForms状態は、POSTに必要なhidden値、選択値、候補だけを保持します。HTML解析木は保持せず、URLを正規化した直近32状態のLRUです。
- 候補取得は単一ワーカーで処理し、利用者操作を先読みより優先します。開始前に古くなった要求は破棄します。
- HTML→PDFの検証子プロセスへHTML本文を転送せず、一時HTMLのパスだけを渡します。Edgeの標準エラーは常時読み取り、診断用の末尾だけを保持します。

## 定期実行のプロセス数と履歴

- Windowsタスクが同時に発火しても、最初に起動したプロセスだけがユーザー単位のcoordination IDに対応するdispatcherになります。coordination IDは`%LOCALAPPDATA%\ippi-down\install-id`に保持し、配置単位のtask namespace IDとは分離します。後続プロセスはFIFO ticketを登録して終了します。
- dispatcherは実ダウンロードを常に1件だけ実行します。結果は`logs/schedule-runs.jsonl`を正本として記録し、GUIはその結果を表示します。
- dispatcherの異常終了は、次の起動時にPIDとticket期限を確認して引き継ぎます。待機上限は2時間、実処理上限は2時間、Windowsタスク全体の上限は4時間です。
- dispatcherはキュー処理中だけ存在する短命プロセスです。常駐トレイ、常駐通知監視、Windowsサービスは起動しません。GUIとジョブが動作していない間に、ippi-down由来のプロセスは存在せず、CPU、メモリ、ネットワークを使用しません。
- 通信、タイムアウト、429、5xxなどの一時障害にだけ、設定された回数と間隔（既定は15分間隔、最大2回）で再試行します。この有界な待機は常時負荷ではなく、GUIでは「再試行待機中」と表示します。
- GUI起動時に各WindowsタスクのXMLを検証し、そのGUIが動作する間は検証結果を保持します。通常pollは全対象タスクを1回のverbose CSV照会で更新します。actionまたはEnabled状態の差分を検出した場合と、アプリ自身が登録・更新・修復した場合にだけXML保持を無効化して再検証します。GUIの通常更新は60秒、実行中・待機中・再試行待機中は5秒間隔です。

## 定期実行の通知資源

- 通知は再試行途中やFIFO受付時ではなく、最終実行履歴を保存した後に`run_id`ごと1回だけ処理します。
- Windows標準の`Shell_NotifyIconW`を使うため、定期実行通知に追加のPython依存と`win10toast`は必要ありません。
- 通知用の非表示ウィンドウ、システムアイコン、メッセージ処理は最大10秒で終了し、成功・失敗のどちらでも後処理します。通知用の常駐スレッドや監視プロセスはありません。
- 集中モードや企業ポリシーで表示されないことはありますが、通知処理の成否はダウンロード結果や終了コードを変えません。`logs/schedule-runs.jsonl`と`logs/app.log`を正本とします。

## 一時成果物の回収

- 通常取得の`.part`は、成功時だけ正式名へ原子的に置換します。失敗・キャンセル時は`.part`だけを削除し、既存の正常ファイルは残します。
- キューの原子的書込み用`.tmp`は、期限を過ぎたものだけを回収します。実行中のticketやプロセスを参照するものは削除しません。
- Edge変換用の一時HTML・専用プロファイル・PDF `.part`は、成功・失敗・キャンセルのすべてで後処理します。後処理だけが失敗した場合は完成PDFを残し、`TEMP_CLEANUP_FAILED`を記録します。
- 設定更新・削除で保留されたスナップショットは、実行中のWindowsタスク、設定単位mutex、全体mutexのいずれにも使用されていないことを確認してから回収します。安全性を確認できない場合は次回照会まで保持します。
- 一時物の作成日時、所有プロセス、用途を記録できる領域ではそれらを確認します。所有状態を確定できない場合は削除せず、期限と次回の安全確認に委ねます。

## 運用上の注意

GUIの表示上限は画面だけに適用されます。調査が必要なときは`logs/app.log`、`logs/schedule-runs.jsonl`、各保存先の`.ippi-download-history.jsonl`を参照してください。これらの履歴・ログやダウンロード済みファイルを、アプリが自動削除することはありません。
