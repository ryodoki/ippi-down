# ブラウザの開発者ツールを使用した手動調査手順書

## 目的

実際のブラウザでのダウンロード動作を確認し、ネットワークリクエストの詳細を記録します。

## 手順

### ステップ1: ブラウザを開く

1. **ChromeまたはEdgeブラウザを開く**
   - 推奨: Chrome（最新版）

2. **開発者ツールを開く**
   - `F12`キーを押す
   - または、右クリック → 「検証」
   - または、メニュー → 「その他のツール」→ 「開発者ツール」

3. **ネットワークタブを開く**
   - 開発者ツールの「Network」（ネットワーク）タブを開く
   - **重要**: 「Preserve log」（ログを保持）にチェックを入れる
   - 「Clear」（クリア）ボタンをクリックして、既存のログをクリア

### ステップ2: サイトにアクセス

1. **検索ページにアクセス**
   ```
   https://www.i-ppi.jp/IPPI/SearchServices/Web/Search/Search/Search.aspx?tab=4
   ```

2. **ページが読み込まれることを確認**
   - 検索フォームが表示されることを確認

### ステップ3: 検索を実行

1. **検索条件を設定**
   - 発注機関: 「国の機関」を選択

2. **「検索開始」ボタンをクリック**
   - 検索結果が表示されることを確認

### ステップ4: 詳細ページを開く

1. **検索結果から1件をクリック**
   - 詳細ページが開くことを確認

2. **詳細ページのURLを記録**
   - ブラウザのアドレスバーのURLをコピー
   - 例: `https://www.i-ppi.jp/IPPI/SearchServices/Web/Koji/Keika/List.aspx?tab=4`

### ステップ5: ファイルをダウンロード

1. **詳細ページで「公告文書」または「経過文書」タブを確認**
   - ファイルリンクが表示されていることを確認

2. **ファイルリンクをクリック**
   - PDFファイルのダウンロードが開始されることを確認

### ステップ6: ネットワークタブでリクエストを確認

1. **PDFファイルのリクエストを探す**
   - ネットワークタブのリクエスト一覧をスクロール
   - `KokaiBunshoServlet`または`pdf`を含むリクエストを探す
   - Content-Typeが`application/pdf`のリクエストを探す

2. **リクエストを選択**
   - PDFファイルのリクエストをクリックして選択

### ステップ7: リクエスト情報を記録

#### 7.1 General（一般）タブ

以下を記録：
- **Request URL**（最終的なURL、リダイレクト後）: `________________________`
- **Request Method**: `________________________`（通常は GET）
- **Status Code**: `________________________`（通常は 200）
- **Remote Address**: `________________________`

#### 7.2 Headers（ヘッダー）タブ

**Request Headers（リクエストヘッダー）**:
- すべてのヘッダーをコピーするか、以下を記録：

```
User-Agent: ________________________
Accept: ________________________
Accept-Language: ________________________
Accept-Encoding: ________________________
Referer: ________________________（重要）
Origin: ________________________（重要）
Cookie: ________________________（すべてのCookie、重要）
Sec-Fetch-Site: ________________________
Sec-Fetch-Mode: ________________________
Sec-Fetch-Dest: ________________________
Sec-Fetch-User: ________________________
Connection: ________________________
Cache-Control: ________________________
Pragma: ________________________
その他のヘッダー: ________________________
```

**Response Headers（レスポンスヘッダー）**:
- すべてのヘッダーをコピーするか、以下を記録：

```
Content-Type: ________________________
Content-Length: ________________________
Location: ________________________（リダイレクトの場合）
Server: ________________________
Date: ________________________
その他のヘッダー: ________________________
```

#### 7.3 Query String Parameters（クエリパラメータ）タブ

以下を記録：
- `AnkenKanriNo`: `________________________`
- `BunshoKanriId`: `________________________`
- その他のパラメータ: `________________________`

#### 7.4 Cookiesタブ

すべてのCookieを記録：

```json
[
  {
    "name": "Cookie名",
    "value": "Cookie値",
    "domain": "ドメイン",
    "path": "パス",
    "secure": true or false,
    "httpOnly": true or false,
    "sameSite": "Strict" or "Lax" or "None"
  }
]
```

#### 7.5 リダイレクトチェーン

**もしリダイレクトがある場合**:
- 「General」タブの下に「Redirects」が表示される
- すべてのリダイレクトURLを記録：

```
1. 最初のURL: ________________________
   Status: 301/302/303/307/308
   
2. 2番目のURL: ________________________
   Status: 301/302/303/307/308
   
3. 最終URL: ________________________
   Status: 200
```

### ステップ8: リクエストをコピー

1. **リクエストを右クリック**
   - 「Copy」→ 「Copy as cURL」を選択
   - cURLコマンドをテキストエディタに貼り付け

2. **または、リクエストヘッダーをコピー**
   - 「Copy」→ 「Copy request headers」を選択
   - リクエストヘッダーをテキストエディタに貼り付け

### ステップ9: 調査結果を記録

`docs/dev/browser_request_template.json`に情報を記入するか、以下の形式で記録：

```json

    },
```

## 自動化スクリプトの使用（オプション）

Seleniumを使用してブラウザの動作を自動記録することもできます：

```bash
# Seleniumをインストール（まだの場合）
pip install selenium

# スクリプトを実行
python scripts/dev/capture_browser_network_requests.py
```

**注意**: 
- Seleniumを使用する場合は、ChromeDriverが必要です
- 手動操作の方が確実な場合があります

## 重要な確認項目

### ✅ 必ず確認すべき項目

1. **リクエストURL**
   - 最終的なURL（リダイレクト後）
   - クエリパラメータを含む完全なURL

2. **Refererヘッダー**
   - どのページからアクセスしているか
   - 詳細ページのURLと一致するか

3. **Cookie**
   - すべてのCookie
   - 特にセッションID（`ASP.NET_SessionId`など）

4. **Originヘッダー**
   - 送信されているか
   - 値は正しいか

5. **Sec-Fetch-*ヘッダー**
   - 送信されているか
   - 値は適切か

6. **リダイレクトチェーン**
   - リダイレクトがあるか
   - どのURLを経由しているか

### ⚠️ 注意事項

- **ネットワークタブは、リクエストが送信される前に開く必要があります**
- 「Preserve log」にチェックを入れないと、リダイレクト後にログが消える可能性があります
- ファイルダウンロードが開始される前に、ネットワークタブでリクエストを確認してください

## トラブルシューティング

### リクエストが見つからない場合

1. **ネットワークタブをクリアして、もう一度試す**
2. **「Preserve log」にチェックが入っているか確認**
3. **ファイルダウンロードリンクをクリックする前に、ネットワークタブを開いているか確認**
4. **Content-Typeでフィルタリング**: 「Filter」に`pdf`または`application/pdf`を入力

### リダイレクトが見つからない場合

1. **「Preserve log」にチェックが入っているか確認**
2. **Generalタブの下に「Redirects」が表示されるか確認**
3. **リクエストの右クリックメニューから「Copy」→ 「Copy as cURL」を選択して、cURLコマンドでリダイレクトチェーンを確認**

## 次のステップ

調査結果を記録したら：

1. **調査結果を分析**
   - `scripts/dev/compare_browser_request.py`を使用して、コードとの差異を確認

2. **コードを修正**
   - 調査結果に基づいて、不足しているヘッダーやCookieを追加
   - リダイレクト処理を改善

3. **再度テスト**
   - 修正後に再度ダウンロードテストを実行
