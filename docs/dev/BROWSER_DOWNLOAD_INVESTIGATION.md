# ブラウザでのダウンロード動作調査手順書

## 問題の現状

- **エラー**: 接続タイムアウト（`e2ppiw01.e-bisc.go.jp`への接続が確立できない）
- **原因候補**: 
  1. Cookieが別ドメインに送信されていない
  2. リダイレクトやセッション管理の流れがコードで再現できていない
  3. 必要なヘッダーやパラメータが不足している可能性

## 調査手順

### ステップ1: ブラウザで実際にダウンロードを試行

1. **ブラウザを開く**
   - ChromeまたはEdgeを使用

2. **開発者ツールを開く**
   - `F12`キーを押す
   - または、右クリック → 「検証」

3. **ネットワークタブを開く**
   - 開発者ツールの「Network」（ネットワーク）タブを開く
   - 「Preserve log」（ログを保持）にチェックを入れる

4. **実際にサイトにアクセスしてファイルをダウンロード**
   ```
   1. https://www.i-ppi.jp/IPPI/SearchServices/Web/Search/Search/Search.aspx?tab=4 にアクセス
   2. 検索条件を設定（例: 発注機関 = "国の機関"）
   3. 「検索開始」をクリック
   4. 検索結果から1件をクリックして詳細ページを開く
   5. 詳細ページで「公告文書」または「経過文書」タブのファイルをクリック
   6. ダウンロードを実行
   ```

## 仮説と検証

### 仮説1: Cookieが別ドメインに送信されていない

**検証方法**:
- ネットワークタブで`e-bisc.go.jp`へのリクエストのCookieを確認
- もしCookieが空なら、別の方法（URLパラメータ、ヘッダー）でセッション情報を渡している可能性

**修正案**:
- Cookieを手動で設定する必要がある可能性
- または、URLにセッション情報を含める必要がある可能性

### 仮説2: リダイレクトがコードで追従されていない

**検証方法**:
- ネットワークタブでリダイレクトチェーンを確認
- コードの`allow_redirects=True`が正しく機能しているか確認

**修正案**:
- リダイレクトを手動で処理する
- 中間URLを経由する必要がある可能性

### 仮説3: 必要なヘッダーが不足している

**検証方法**:
- ブラウザで送信されているヘッダーと、コードで送信しているヘッダーを比較

**修正案**:
- 不足しているヘッダーを追加
- 特に`Origin`, `Sec-Fetch-*`などの新しいヘウダーを追加

### 仮説4: URLパラメータが間違っている

**検証方法**:
- 実際のブラウザでのURLと、コードで生成しているURLを比較
- パラメータの順序やエンコーディングを確認

**修正案**:
- URLの生成方法を修正
- パラメータの順序を統一

### 仮説5: 詳細ページから直接ダウンロードできない（中継が必要）

**検証方法**:
- 詳細ページのHTMLを確認し、ダウンロードリンクがどのように生成されているか確認
- JavaScriptで動的に生成されている可能性

**修正案**:
- JavaScriptを実行してダウンロードURLを生成
- または、Seleniumなどのブラウザ自動化ツールを使用

## 参考: 現在のコードの問題点

現在の分析結果から判明している問題点：

1. **Cookieのドメイン不一致**
   - 現在のCookie: `www.i-ppi.jp`
   - ダウンロード先: `e2ppiw01.e-bisc.go.jp`
   - **Cookieが別ドメインに送信されない**

2. **直接アクセスできない可能性**
   - `e2ppiw01.e-bisc.go.jp`に直接接続しようとしている
   - ブラウザでは、詳細ページからリンクをクリックした際の処理が異なる可能性

3. **リダイレクトの追従が必要かもしれない**
   - ブラウザでは、詳細ページ→中継ページ→ダウンロードの流れがある可能性
